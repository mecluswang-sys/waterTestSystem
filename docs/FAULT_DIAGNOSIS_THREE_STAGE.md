# 三段式故障定位表（命令发出 -> 主控执行 -> PLC反馈）

目的：把控制链路问题快速归因到具体层，避免“看起来像网络问题”的误判。

## 1. 诊断原则

- Stage A：命令是否从 Station 成功发出。
- Stage B：Terminal 是否收到并执行命令。
- Stage C：PLC 是否反馈了正确状态变化。

结论规则：
- A 失败：优先排查 Station 侧连接与命令构造。
- A 成功、B 失败：优先排查 Terminal 接收与路由。
- A/B 成功、C 失败：优先排查 PLC 通信、地址映射或现场设备。

## 2. 快速定位矩阵

| 现象 | Stage A | Stage B | Stage C | 最可能根因 |
|------|---------|---------|---------|------------|
| 点击按钮无任何反应 | 失败 | 未知 | 未知 | Station 未连接或按钮未走远程分支 |
| Station 提示已发送，但主控无记录 | 成功 | 失败 | 未知 | 主控监听/反序列化/路由异常 |
| 主控显示执行成功，但设备不动作 | 成功 | 成功 | 失败 | PLC 地址映射、设备回路、线缆/IO 异常 |
| 设备动作但 UI 不更新 | 成功 | 成功 | 成功 | 回读链路或 UI 刷新逻辑异常 |

## 3. 标准诊断步骤

### Step 1: 确认 Stage A（Station）

检查项：
- Station 是否显示“已连接到主控台”。
- 触发操作后是否有“发送成功/失败”反馈。
- 严格远程模式是否开启（station.strict_remote_mode=true）。

### Step 2: 确认 Stage B（Terminal）

检查项：
- Terminal 是否收到 COMMAND_REQUEST。
- Terminal 是否进入对应命令执行分支（relay/pump/valve）。
- Terminal 是否回发 ACK/COMMAND_RESPONSE（如有）。

记录：
- B 结论：通过/失败
- 证据：

### Step 3: 确认 Stage C（PLC/设备）

检查项：
- PLC 连接是否在线。
- 对应 DB/Q 区位是否变化。
- 现场设备是否动作（阀、泵、继电器）。
- 动作后状态是否回传到 UI。

## 5. 常见问题与建议

1. 仅个别页面失败，其他页面正常：
优先看页面是否仍有本地回退逻辑未覆盖。

2. 首次操作失败，第二次成功：
优先看连接建立初期的命令发送时机和状态同步。

3. 主控执行成功但状态回显慢：
优先看采样周期、UI 刷新周期与回读路径是否一致。

4. 长时间运行后偶发失败：
优先做重连压力测试并对照本仓库联调日志模板记录。
