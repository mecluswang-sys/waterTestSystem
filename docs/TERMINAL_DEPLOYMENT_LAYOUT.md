**优点**

```
❌ 难点2：通信协议需要转换
   → 需要在PLC或中间件做协议转换
   → 我们的TCP:5555协议需要适配PROFINET

❌ 难点3：编程环境差异
   → 需要学习TIA Portal编程
   → C++代码无法直接移植
```

**👍 适用场景**:

- 完全基于Siemens生态的工业系统

**👎 不适用场景**:

### CAT6网线标准

| 参数 | 规格 |
|------|------|
| 最大传输距离 | 100米 (10米无损) |
| 传输速率 | 10/100/1000 Mbps |
| 抗干扰能力 | 强（屏蔽对绞） |
| 安装难度 | 简单（RJ45接头） |
| 成本 | 20-30元/米 |

### 实际施工建议

```
✅ 建议做法：
1. 使用专业布线工具（打线钳、网线测试仪）
2. 网线铺设在PVC管/电源管中
3. 避免与电源线平行（>30cm距离）
4. 每10米使用一个中继器/交换机
5. 使用屏蔽网线（在工业环境中）
6. 连接器使用屏蔽RJ45头

❌ 避免：
1. 网线直接暴露在空气中
2. 网线与电源线绑定
3. 拉伸过紧导致损伤
4. 使用非屏蔽网线
5. 拐角过急（半径<5cm）
```

## 🚀 **系统启动流程**

### 第1步：硬件接线

```
1. 网线接入交换机的16个端口
2. PC连接交换机
3. 4台终端连接交换机
4. PC连接PLC（既有）
```

### 第2步：配置网络IP

在**每台终端和PC上**运行：

```powershell
# 打开网络设置 → 更改适配器设置
# 右键网卡 → 属性 → IPv4 → 属性

# 设置固定IP (以终端1为例)
$adapter = Get-NetAdapter | Where-Object {$_.Name -like "*Ethernet*"}

# 删除旧配置
Remove-NetIPAddress -InterfaceIndex $adapter.InterfaceIndex -Confirm:$false -ErrorAction SilentlyContinue

# 设置新IP
New-NetIPAddress -InterfaceIndex $adapter.InterfaceIndex `
  -IPAddress 192.168.33.11 `
  -PrefixLength 24 `
  -DefaultGateway 192.168.33.1
```

### 第3步：验证连接

```powershell
# 在PC上测试所有终端
ping 192.168.33.11  # 终端1
ping 192.168.33.12  # 终端2
ping 192.168.33.13  # 终端3
ping 192.168.33.14  # 终端4
ping 192.168.33.1   # PLC

# 预期: 都能收到回复 (Reply from ...)
```

### 第4步：启动系统

**在PC上**:

```bash
# 启动Terminal Server
WaterTestSystem.exe --mode terminal
```

**在每台终端上** (或远程启动):

```bash
# 终端1
WaterTestSystem.exe --mode station --id 1 --host 192.168.33.100 --name "操作台1"

# 终端2
WaterTestSystem.exe --mode station --id 2 --host 192.168.33.100 --name "操作台2"

# 终端3
WaterTestSystem.exe --mode station --id 3 --host 192.168.33.100 --name "操作台3"

# 终端4
WaterTestSystem.exe --mode station --id 4 --host 192.168.33.100 --name "操作台4"
```

## ⚠️ **常见问题排查**

### 问题1：终端无法连接PC

```
故障现象: 终端显示"连接失败"

排查步骤:
1. ping 192.168.33.100 (PC地址)
2. netstat -an | find ":5555"  (检查端口)
3. 检查防火墙设置 (允许TCP:5555)
4. 重启Terminal Server进程

解决方案:
• 检查网线是否松动
• 重新配置PC IP地址
• 重启交换机
• 检查PC的防火墙规则
```

### 问题2：数据传输延迟大

```
故障现象: 终端数据显示滞后

原因分析:
1. 网线质量不好 (CAT5改为CAT6)
2. 交换机端口故障 (更换端口)
3. PC性能不足 (升级CPU)
4. 网络拥塞 (停止其他应用)

排查步骤:
• ping 延迟 >10ms = 网络问题
• 检查CPU占用 >80% = 性能问题
• 运行网络性能测试工具

解决方案:
• 更换为CAT6屏蔽网线
• 更换交换机或升级端口
• 升级PC硬件
• 关闭不必要的后台进程
```

### 问题3：某个终端断连

```
故障现象: 某个终端突然掉线

原因分析:
1. 网线接头松动
2. 交换机端口故障
3. 终端网卡驱动问题
4. PC进程崩溃

排查步骤:
1. 检查物理连接
2. 尝试更换交换机端口
3. 更新网卡驱动
4. 查看Terminal Server日志
5. 检查PC是否宕机

解决方案:
• 重新插拔网线
• 更换交换机端口
• 重启网卡驱动
• 重启Terminal Server
• 查看系统日志
```
