# 西门子 HMI 接入方案

文档编号: WTS-HMI-INTEGRATION-20260908
版本: v1.0
日期: 2026-09-08

## 1. 目标与边界

在既有一台 PC 和一台 Siemens S7 PLC 的水质测试系统中增加一台西门子 HMI。HMI 用于现场显示、报警确认和经授权的操作；PC 保留测试流程、数据记录、报表和现有 Qt 界面能力。

HMI 通过以太网使用 S7/PROFINET 通讯直接连接 PLC，无需在 PC 与 HMI 之间增加协议转换网关。

> 本方案的关键约束：PC 和 HMI 均不得直接写物理输出位。两者只能写入各自的命令请求区，由 PLC 程序完成联锁、权限校验、优先级仲裁和最终输出。

## 2. 网络拓扑

```text
                         工业以太网交换机
                    +-----------+-----------+
                    |           |           |
                    v           v           v
             +----------+ +----------+ +----------+
             | PC       | | S7 PLC   | | Siemens  |
             | Terminal | | 192.168 | | HMI      |
             | / Qt GUI | | .33.1   | | WinCC    |
             +----------+ +----------+ +----------+
                    |           ^           |
                    | S7 读写   |           | S7 读写
                    +-----------+-----------+

PC:  192.168.33.100
PLC: 192.168.33.1
HMI: 192.168.33.2（操作台 1，已确认）
掩码: 255.255.255.0
```

- PLC 的 S7 服务端口为 `102`，PC 与 HMI 可各自建立独立 S7 会话。
- HMI 工程在 TIA Portal/WinCC 中配置 PLC 的固定 IP，不连接 PC 的 `5555` Terminal 服务。
- 现有 Terminal-Station 的 TCP 通讯不变；HMI 是 PLC 层设备，不替代 Station Client。

## 3. 职责分工

| 功能 | PC（Terminal/Qt） | PLC | Siemens HMI（WinCC） |
|---|---|---|---|
| 实时采集与记录 | 读取、记录、上报 | 提供过程数据 | 读取、显示趋势 |
| 流程执行 | 发出流程请求、显示结果 | 最终状态机与联锁 | 显示当前步骤 |
| 设备控制 | 写入 PC 命令请求区 | 仲裁请求并驱动输出 | 写入 HMI 命令请求区 |
| 安全急停 | 显示状态，不作为唯一安全措施 | 硬件/程序安全逻辑 | 显示状态，不作为唯一安全措施 |
| 报警 | 记录、显示 | 生成、锁存报警 | 显示、确认可确认报警 |

急停、超压、防夹等安全回路必须由硬接线和 PLC 安全逻辑保证，不能依赖 HMI、PC 软件或网络通讯。

## 4. PLC 数据块接口

在 PLC 中新增或冻结一个对外 HMI 接口 DB，例如 `DB_WTS_HMI`。请关闭该 DB 的优化访问，并在 TIA Portal 中为 HMI 和 PC 使用符号访问或已冻结的绝对地址。

| 区域 | 方向 | 建议内容 | 规则 |
|---|---|---|---|
| `Status` | PLC -> PC/HMI | 模式、步骤、运行、急停、报警码、通信心跳 | 只读 |
| `Process` | PLC -> PC/HMI | 压力、流量、温度、阀门反馈、泵反馈、测试结果 | 只读 |
| `CmdFromPc` | PC -> PLC | 启停、复位、配方选择、手动控制请求、序号 | PC 仅写此区 |
| `CmdFromHmi` | HMI -> PLC | 启停、复位、报警确认、手动控制请求、序号 | HMI 仅写此区 |
| `CommandResult` | PLC -> PC/HMI | 接收序号、执行结果、拒绝原因、当前控制源 | 只读 |
| `Config` | PC -> PLC | 经版本控制的工艺参数 | HMI 默认只读 |

`CmdFromPc` 与 `CmdFromHmi` 必须使用独立的命令序号和确认序号。客户端写入命令参数后递增命令序号；PLC 只在检测到新序号时消费一次，并将确认结果写回 `CommandResult`。这避免通讯抖动导致命令重复执行。

## 5. 控制仲裁规则

PLC 对每个控制请求依序执行以下判断：

1. 安全回路、急停、关键故障有效时，拒绝普通控制请求并进入安全输出状态。
2. 自动测试运行时，仅接受状态机允许的停止、急停和受控暂停请求；拒绝手动阀泵动作。
3. 手动模式下，取得控制权的来源可执行允许的操作；另一来源的同类请求返回“控制权被占用”。
4. HMI 的报警确认仅清除已解除且允许确认的报警，不得绕过故障联锁。
5. PLC 将最终执行结果、拒绝原因和控制源回写给 PC 与 HMI，二者均以该回读结果更新界面。

建议控制源枚举：`0=无`、`1=PC`、`2=HMI`、`3=PLC自动`。切换控制源需要操作员登录权限，并在 HMI 与 PC 上明确显示。

## 6. HMI 画面最小范围

第一阶段 HMI 工程至少提供以下画面：

1. 总览：系统模式、当前步骤、三路压力、流量、关键阀泵反馈、通信状态。
2. 测试：配方只读信息、运行进度、开始/停止/复位请求及其执行结果。
3. 手动：经权限控制的阀门和泵操作，请求与反馈必须并列显示。
4. 报警：活动报警、历史报警、确认操作与报警帮助文本。
5. 趋势：压力、流量和关键状态的实时趋势；刷新周期不大于 200 ms。
6. 维护：HMI/PLC 通讯诊断、DB 版本、当前控制源和 I/O 状态。

界面变量使用 PLC 的工程单位。当前压力链路以 DB6 的 `REAL` 原值为准，PC、HMI 均不得各自定义不同的缩放比例。

## 7. 实施步骤

1. 在 TIA Portal 项目中添加实际 HMI 型号，配置固定 IP 与 PLC S7 连接。
2. 在 PLC 创建 `DB_WTS_HMI`，实现命令序号、权限、互锁和 PC/HMI 仲裁；不要让 HMI 标签映射到 Q 输出或原有内部执行位。
3. 为 `Status`、`Process`、`CommandResult` 创建 HMI 外部变量，为 `CmdFromHmi` 创建受控写变量。
4. 在 PC 侧将新增 DB 作为统一接口；完成迁移前，禁止 PC 与 HMI 同时操作相同执行器。
5. 下载 PLC 与 HMI 工程，先用 PLCSIM 或断开现场执行器进行命令确认和拒绝路径测试。
6. 完成现场联调后，冻结 DB 版本、HMI 工程版本和变量表，并归档到项目交付物。

## 8. 联调验收

- HMI 断网、重启或通讯超时不得改变 PLC 输出状态，也不得阻断 PC 数据记录。
- PC 与 HMI 同时请求同一手动控制时，PLC 只执行获授权来源的一个请求，并在两端返回明确结果。
- 任一来源在 500 ms 内获得命令接受或拒绝反馈；状态显示刷新周期不大于 200 ms。
- 急停、超压、防夹、传感器异常触发时，PLC 在不依赖 PC/HMI 的条件下进入安全状态。
- HMI 显示值与 PLC 在线监控、PC 记录值的量纲和有效位一致。
- `DB_VERSION` 或 `DB_LAYOUT_ID` 不匹配时，HMI 和 PC 显示版本不匹配，禁止写入命令请求区。

## 9. 待现场确认

- HMI 准确型号、屏幕尺寸、WinCC Runtime/Comfort 授权类型。
- PLC CPU 型号、固件版本和可用以太网口数量。
- 现场最终 IP 地址、交换机型号及 VLAN/防火墙策略。
- 是否需要配方编辑、用户权限审计、历史趋势和数据归档到 PC。
- `DB_WTS_HMI` 的最终 DB 编号、绝对地址及版本号。
