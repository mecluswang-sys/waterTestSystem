# 2026-04-27 站1 M100 控制链路修改日志

## 一、修改背景

今天的修改集中在 1 号操作台流程图阀门图元与 PLC `M100.0 ~ M100.3` 控制链路的一致性问题，主要目标有 4 个：

1. 将站 1 流程图上 4 个关键阀门的点击控制统一切到 `M100.0 ~ M100.3`。
2. 统一这 4 个阀门的点击逻辑、图元联动、自动复位提示与防抖行为。
3. 修复界面已改成 M 位、但 `DeviceManager` 底层仍部分写 Q 区导致的控制异常。
4. 明确当前数据采集频率、界面刷新频率与继电器状态刷新频率，便于后续联调。

## 二、核心修改

### 1. Station1Panel 继电器地址映射调整为 M100.0 ~ M100.3

- 将 1 号操作台前 4 路关键阀门地址映射调整为：
  - index 0 -> `M100.0`
  - index 1 -> `M100.1`
  - index 2 -> `M100.2`
  - index 3 -> `M100.3`
- 保留 index 4 及之后继续走原 Q 区路径。

涉及文件：

- `src/gui/Station1Panel.cpp`

### 2. 4 个阀门图元统一改为“直接继电器点击控制”

- 上排第 1 个阀门图元绑定到 relay index 0。
- 上排第 2 个阀门图元绑定到 relay index 1。
- 下排左侧阀门图元绑定到 relay index 2。
- 下排待测阀图元绑定到 relay index 3。
- 以上图元全部：
  - 清空 `data(3)`，不再走阀门弹窗控制。
  - 设置 `data(4)` 作为继电器索引。
  - 关闭 selectable，统一走图元点击切换路径。

涉及文件：

- `src/gui/Station1Panel.cpp`

### 3. M100.0 ~ M100.3 点击逻辑统一

- 新增 `isM100RelayIndex()`，统一判断 index `0 ~ 3`。
- 原先只对 `M100.0` 生效的逻辑，扩展到 `M100.0 ~ M100.3`：
  - 点击防抖
  - 自动复位提示
  - 图元开关状态联动
  - 乐观 UI 刷新后的回读跟踪
- 将原先单值状态改为数组状态，避免不同位之间互相干扰：
  - `m_expectM100Hold`
  - `m_expectM100SetMs`
  - `m_lastM100ToggleMs`

涉及文件：

- `include/gui/Station1Panel.h`
- `src/gui/Station1Panel.cpp`

### 4. 阀门名称与 M100 地址重新对应

- 为避免界面名称与地址映射错位，将 4 个阀门图元名称重新整理为对应电磁阀名称。
- 目的不是单纯改字，而是让界面名称、relay 地址、点击行为三者一致，减少联调误判。

涉及文件：

- `src/gui/Station1Panel.cpp`

### 5. 根因修复：DeviceManager 底层读写路径统一为 M100.0 ~ M100.3

- 发现问题根因：
  - `Station1Panel` 界面层已经把前 4 路当成 `M100.0 ~ M100.3`。
  - 但 `DeviceManager::setRelay()` / `getRelayState()` 只有 index 0 走 M 区。
  - index 1 / 2 / 3 仍然走 Q 区读写，导致“PLC 手动改 M100.1 与程序点击行为不一致”。
- 已修复为：
  - index `0 ~ 3` 全部写 `M100.0 ~ M100.3`
  - index `0 ~ 3` 全部读 `M100.0 ~ M100.3`
  - 日志中明确打印 `index` 和 `M100.x` 地址，便于继续跟踪

涉及文件：

- `src/DeviceManager.cpp`
